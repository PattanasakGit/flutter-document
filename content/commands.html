วิธีใช้ Command Cookbook

รันจาก root ที่มี pubspec.yaml เว้นแต่ระบุเป็นอย่างอื่น อ่าน output ก่อนรันคำสั่งถัดไป และอย่าใช้ clean/reset เป็นการแก้แบบสุ่ม

SDK และ environment

Commandใช้เมื่ออ่านอะไรจากผลลัพธ์
flutter --versionยืนยัน SDKFlutter/Dart version และ channel
flutter doctor -vตรวจ toolchainเฉพาะ platform ที่ทีมรองรับต้องพร้อม
flutter devicesหา targetdevice id/platform
flutter emulatorsดู emulatorid ที่ใช้ launch
flutter config --listดู feature flags SDKplatform enablement
dart --versionยืนยัน Dart ที่ใช้งานต้องสัมพันธ์กับ Flutter SDK

Clone และ baseline

เริ่มจาก clean checkout
git clone <repository-url> my_app
cd my_app
git status --short --branch
flutter pub get
dart run build_runner build
flutter analyze
flutter test
flutter run -t lib/main_development.dart

ถ้า repository มี Flutter version manager ให้ใช้ command wrapper ที่โครงการกำหนด และไม่เปลี่ยน lockfile โดยไม่ตั้งใจ

Dependencies

Commandความหมายข้อควรระวัง
flutter pub getresolve ตาม pubspec/lockตรวจ lockfile diff
flutter pub add packageเพิ่ม runtime dependencyต้องมีเหตุผล/owner
flutter pub add --dev packageเพิ่ม dev dependencyไม่เข้า production runtime โดยตรง
flutter pub depsดู dependency treeใช้หา transitive conflict
flutter pub outdatedดู version ที่ล้าหลังไม่ได้แปลว่าต้อง upgrade ทั้งหมด
dart pub cache repairซ่อม pub cacheใช้เมื่อพิสูจน์ว่า cache เสีย

Code generation

One-shot และ watch
dart run build_runner build
dart run build_runner watch
  • ใช้ build ใน CI และก่อน commit
  • ใช้ watch ระหว่างแก้ annotation ต่อเนื่อง
  • ถ้า conflict ให้ตรวจ source/generated ownership ก่อนลบไฟล์
  • อย่าแก้ *.g.dart หรือ *.freezed.dart ด้วยมือ

Format และ analyze

Local fix และ CI check
# จัด format
dart format .

# ตรวจว่า format แล้วโดยไม่แก้ไฟล์
dart format --output=none --set-exit-if-changed .

# Static analysis
flutter analyze

Testing

CommandScope
flutter testunit/widget tests ทั้งหมด
flutter test test/features/tasksfocused directory
flutter test --name "creates a task"test ตามชื่อ
flutter test --coverageสร้าง coverage/lcov.info
flutter test integration_testintegration ตาม target/support ปัจจุบัน
flutter test --update-goldensอัปเดต golden โดยตั้งใจ

ตรวจ golden diff ด้วยภาพ ไม่ commit เพราะ command ผ่านอย่างเดียว integration command อาจต้องระบุ -d <device-id> ตาม platform

Run และ debugging

Target และ environment
flutter run -t lib/main_development.dart
flutter run -d chrome -t lib/main_development.dart
flutter run -d <device-id> --profile
flutter run \
  -t lib/main_staging.dart \
  --dart-define=API_BASE_URL=https://staging.example.com

ระหว่าง flutter run: กด r เพื่อ hot reload, R เพื่อ hot restart, q เพื่อหยุดอย่างเรียบร้อย

Build artifacts

Common builds
flutter build apk --release -t lib/main_production.dart
flutter build appbundle --release -t lib/main_production.dart
flutter build ios --release -t lib/main_production.dart
flutter build ipa --release -t lib/main_production.dart
flutter build web --release -t lib/main_production.dart

iOS ต้องใช้ macOS/Xcode; store build ต้องมี signing/environment จริง อ่านรายละเอียดในบท Build & Release ก่อนแจก artifact

Commandใช้เมื่อ

Clean อย่างมีเหตุผล

ใช้เมื่อ artifact stale ถูกพิสูจน์แล้ว
flutter clean
flutter pub get
dart run build_runner build

flutter clean ลบ build outputs ไม่แก้ logic bug, invalid state, network failure หรือ dependency incompatibility

Git safety chain

ก่อน commit
git status --short --branch
git diff --stat
git diff
git diff --check
git add <explicit-paths>
git diff --cached
git commit -m "feat(tasks): add task management flow"

ระบุ path ตอน stage เพื่อไม่รวมไฟล์ส่วนตัว/generated artifact ที่ไม่ตั้งใจ และตรวจ author ด้วย git log -1 --format=fuller

ก่อนเปิด PR

Recommended chain
dart run build_runner build
dart format --output=none --set-exit-if-changed .
flutter analyze
flutter test
git diff --check
git status --short

อ่าน exit code

Exit code 0 หมายถึง command สำเร็จตามสิ่งที่มันตรวจเท่านั้น เช่น flutter analyze ผ่านไม่ได้พิสูจน์ runtime flow และ flutter build ผ่านไม่ได้พิสูจน์ backend หรือ store compliance

ข้อผิดพลาดที่พบบ่อย

  • copy command โดยไม่รู้ working directory
  • ใช้ latest dependency โดยไม่อ่าน lockfile/API migration
  • รัน full suite อย่างเดียวจน feedback ช้า แทน focused → full
  • ลบ cache หลายชั้นพร้อมกันจนวิเคราะห์สาเหตุไม่ได้
  • ส่ง secret ผ่าน command line ที่ shell history/CI log มองเห็น
