สมมติ API contract

Response shape
{
  "data": [
    {
      "id": "task-1",
      "title": "Learn Dart",
      "description": "Practice records",
      "completed": false,
      "created_at": "2026-07-24T10:00:00Z"
    }

}

JSON เป็น untrusted input แม้ backend ทีมเดียวกัน ต้องทดสอบ missing key, wrong type, null และ invalid date ไม่ใช้ as กระจายโดยไม่มี mapping policy

DTO และ JSON mapping

Checked decoder จาก task_dto.dart
factory TaskDto.fromJson(Object? value) {
  final json = _objectMap(value, location: 'task');
  final id = _requiredString(json, 'id');
  final title = _requiredString(json, 'title');
  final description = switch (json['description']) {
    null => '',
    final String value => value,
    _ => throw const SchemaAppException(
      message: 'Task description must be a string.',
    ),
  };
  final completed = json['completed'];
  if (completed is! bool) {
    throw const SchemaAppException(
      message: 'Task completed must be a boolean.',
    );
  }
  final createdAt = DateTime.tryParse(
    _requiredString(json, 'created_at'),
  );
  if (createdAt == null) {
    throw const SchemaAppException(
      message: 'Task created_at must be an ISO-8601 timestamp.',
    );
  }
  return TaskDto(
    id: id,
    title: title,
    description: description,
    completed: completed,
    createdAt: createdAt,
  );
}

implementation จริงตรวจ root object, list, ทุก required field และชนิดข้อมูล ก่อนสร้าง DTO ดูไฟล์ task_dto.dart โดย schema ที่ผิดจะเป็น SchemaAppException และถูก map เป็น SchemaFailure ไม่ปล่อย TypeError ข้าม boundary

Remote datasource

DioTaskRemoteDatasource ที่รันและทดสอบจริง
final class DioTaskRemoteDatasource
    implements TaskRemoteDatasource {
  const DioTaskRemoteDatasource(this._client);
  final ApiClient _client;

  Future<List<TaskDto>> readAll() {
    return _client.get<List<TaskDto>>(
      ApiEndpoint.tasks,
      decoder: TaskDto.decodeList,
    );
  }

  Future<TaskDto> update(
    String id,
    TaskUpdateRequestDto request,
  ) {
    final taskPath =
        '${ApiEndpoint.tasks}/${Uri.encodeComponent(id)}';
    return _client.put<TaskDto>(
      taskPath,
      data: request.toJson(),
      decoder: TaskDto.fromEnvelope,
    );
  }
}

interface ครบ read/create/update/toggle/delete อยู่ที่ task_remote_datasource.dart และ ApiClient มี typed decoder สำหรับ GET/POST/PUT/PATCH/DELETE

Create request DTO

Request body
final class CreateTaskRequestDto {
  const CreateTaskRequestDto({
    required this.title,
    required this.description,
  });
  final String title;
  final String description;

  Map<String, Object?> toJson() => {
    'title': title,
    'description': description,
  };
}

Request DTO แยกจาก Task entity เพื่อไม่ส่ง internal fields เช่น local createdAt/completion policy โดยไม่ตั้งใจ ทั้ง create และ update DTO อยู่ใน task_write_request_dto.dart

Composition ที่ตั้งใจให้ opt-in

Provider ที่มีอยู่จริง แต่ไม่เปลี่ยน offline default
final taskRemoteDatasourceProvider =
    Provider<TaskRemoteDatasource>(
  (ref) => DioTaskRemoteDatasource(
    ref.watch(apiClientProvider),
  ),
);

final remoteTaskRepositoryProvider =
    Provider<TaskRepository>(
  (ref) => RemoteTaskRepository(
    datasource: ref.watch(taskRemoteDatasourceProvider),
    errorMapper: const ErrorMapper(),
    logger: ref.watch(appLoggerProvider),
  ),
);

runnable capstone ยังใช้ taskRepositoryProvider แบบ in-memory เพื่อให้ clone แล้วรัน offline ได้ ส่วน integration จริงต้อง override เป็น remoteTaskRepositoryProvider เฉพาะเมื่อ base URL, auth lifecycle, API contract และ backend พร้อมแล้ว ถ้า config production ขาดให้ fail bootstrap ไม่ fallback เงียบ ๆ ไป fake/local

RemoteTaskRepository rehydrate DTO ผ่าน domain validation และ map exception เป็น typed Result<T>; contract tests อยู่ใน remote_task_repository_test.dart

Transport security checklist

  • HTTPS และ certificate policy
  • timeout แยก connect/send/receive
  • auth header injection จาก session abstraction
  • redact token/password/body ใน logs
  • 401 refresh queue ป้องกันหลาย request refresh พร้อมกัน
  • schema/version compatibility และ observability

ข้อผิดพลาดที่พบบ่อย

  • ใช้ public API เป็น dependency ของ onboarding/test ทั้งหมด
  • map JSON ใน Widget
  • catch เฉพาะ DioException แล้วปล่อย schema error raw
  • ส่ง Entity.toJson เป็น request ทุก endpoint
  • fallback Production ไป fake datasource เมื่อ config ขาด
