เป้าหมายของบท

  • อ่าน T และ T? เป็นคนละ state space
  • ใช้ promotion, ?., ?? และ pattern แทนการกด !
  • แปลง List/Map/Set โดยไม่สร้าง side effect ที่ซ่อนอยู่
  • ใช้ collection-if, collection-for และ spread สร้าง Widget/list

Null safety คือการออกแบบ state

Dart
String? description;

if (description != null) {
  // promoted เป็น String ภายใน block
  print(description.length);
}

final visibleText = description?.trim().isNotEmpty == true
    ? description!.trim()
    : 'ไม่มีรายละเอียด';

ตัวอย่างสุดท้ายยังใช้ ! แม้มีเหตุผล แต่เขียนให้ promotion ชัดกว่าจะอ่านง่ายกว่า:

หลีกเลี่ยง !
String displayDescription(String? value) {
  final trimmed = value?.trim();
  if (trimmed == null || trimmed.isEmpty) {
    return 'ไม่มีรายละเอียด';
  }
  return trimmed;
}

Syntaxความหมายใช้เมื่อ
T?type ยอมรับ nullnull มีความหมายใน domain/UI
value?.xเรียกเมื่อไม่ nullผล null ต่อได้อย่างปลอดภัย
a ?? bfallback เมื่อ a nullมี default ที่ถูก domain
a ??= bกำหนดเมื่อ nulllazy initialize mutable variable
value!บังคับว่าไม่ nullมี invariant ที่พิสูจน์ได้แต่ analyzer ไม่เห็น
lateสัญญาว่ากำหนดก่อนอ่านlifecycle/framework บังคับ initialization ภายหลัง

List, Set และ Map

Collections
final tasks = <Task>[taskA, taskB];
final selectedIds = <String>{'a', 'b'};
final byId = <String, Task>{
  for (final task in tasks) task.id: task,
};

final openTitles = tasks
    .where((task) => !task.isCompleted)
    .map((task) => task.title)
    .toList(growable: false);

Iterable จาก where/map เป็น lazy จนถูก iterate ใช้ toList(growable: false) เมื่อ boundary ต้องการ snapshot ที่ caller เพิ่มสมาชิกไม่ได้

Collection-if, for และ spread

สร้าง Widget list แบบ declarative
Column(
  children: [
    const Text('Tasks'),
    if (isLoading) const CircularProgressIndicator(),
    for (final task in visibleTasks)
      TaskCard(task: task),
    ...extraActions,
  ],
)

นี่ไม่ใช่ template directive แยกภาษาเหมือน JSX expression แต่เป็น collection literal ของ Dart โดยตรง compiler จึงตรวจ type ของสมาชิกทุกตัว

Patterns และ destructuring

Dart 3 pattern
Object payload = {'id': 't1', 'completed': false};

if (payload case {
  'id': final String id,
  'completed': final bool completed,
}) {
  print('$id: $completed');
}

Pattern ช่วยตรวจ shape และ bind type พร้อมกัน แต่ API payload ใน production ควรผ่าน DTO decoder ที่ทดสอบได้ ไม่กระจาย map pattern ไปทุก layer

Pattern switch กับ sealed state

Exhaustive UI mapping
Widget body = switch (state) {
  TaskLoading() => const LoadingView(),
  TaskReady(:final tasks) => TaskList(tasks: tasks),
  TaskFailed(:final failure) => AppErrorView(
    title: 'Tasks unavailable',
    message: failure.userMessage,
  ),
};

รูปแบบนี้ทำให้ loading พร้อม error หรือ success ที่ไม่มี data เกิดไม่ได้ ต่างจาก enum + nullable fields ที่สร้าง combination ผิดได้

Collection immutability

ส่ง snapshot ไม่ส่ง mutable source
List<Task> get tasks => List.unmodifiable(_tasks);

// หลีกเลี่ยง เพราะ caller แก้ state ภายในได้
List<Task> get tasks => _tasks;

ข้อผิดพลาดที่พบบ่อย

  • ใส่ ! หลังทุก API field แทนการ validate schema
  • ใช้ late กับค่าที่จริงควรผ่าน constructor
  • คืน internal mutable list จาก repository
  • เรียก first โดยไม่รู้ว่า list ว่างได้หรือไม่
  • ใช้ map เพื่อ side effect แทน for
