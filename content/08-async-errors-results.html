เป้าหมายของบท

  • แยก synchronous value, Future และ Stream
  • เข้าใจ event loop ในระดับที่ป้องกัน UI blocking และ stale async result
  • วาง exception boundary และ typed failure
  • ใช้ sealed Result กับ exhaustive switch

Future และ async/await

Dart async
Future<List<Task>> loadTasks() async {
  final response = await apiClient.get<List<Object?>>('/tasks');
  return response.map(TaskDto.fromJson).map((dto) => dto.toEntity()).toList();
}

Function ที่มี async คืน Future ทันที เมื่อถึง await execution ยอมคืน control ให้ event loop ไม่ได้สร้าง thread ใหม่อัตโนมัติ งาน CPU หนักยัง block UI isolate

เทียบกับ JavaScript Promise mental model ของ await คล้ายกัน แต่ Dart มี type ของ Future<T>, isolate และ Flutter lifecycle ที่ต้องตรวจ mounted ก่อนใช้ context หลัง async gap

BuildContext หลัง await

Presentation guard
onPressed: () async {
  final saved = await controller.save();
  if (!context.mounted) return;

  if (saved) {
    Navigator.of(context).pop();
  }
}

ระหว่าง await ผู้ใช้อาจปิดหน้า Element ที่ context อ้างถึงถูก unmount การใช้ context ต่อโดยไม่ตรวจทำให้เกิด lifecycle error

Stream สำหรับค่าหลายเหตุการณ์

Stream
Stream<int> countdown(int from) async* {
  for (var value = from; value >= 0; value -= 1) {
    yield value;
    await Future<void>.delayed(const Duration(seconds: 1));
  }
}

await for (final value in countdown(3)) {
  print(value);
}

ใช้ Stream เมื่อ source ส่งหลายค่า เช่น connectivity, WebSocket หรือ database watch อย่าเปลี่ยน Future ที่คืนครั้งเดียวเป็น Stream เพียงเพราะ “reactive”

วาง exception boundary

error pipeline รักษารายละเอียด diagnostic ภายในและให้ presentation รับเฉพาะ failure ที่ตัดสินใจได้ เช่น retry, login ใหม่ หรือแก้ input

Sealed Result

Consume Result
final result = await repository.getTasks();

return switch (result) {
  Success(:final data) => TaskReady(tasks: data),
  Error(:final failure) => TaskFailed(failure: failure),
};

expected failure เช่น network unavailable ไม่จำเป็นต้องใช้ try/catch ทุก controller เพราะ repository เปลี่ยนเป็น value ที่ exhaustively handle ได้

Stale result และ duplicate submission

ปุ่ม async ต้อง disable ระหว่างส่ง และ controller ต้องตัดสินใจเมื่อ request เก่ากลับมาหลัง request ใหม่ วิธีพื้นฐานคือเก็บ operation ID หรือไม่เปิด concurrent operation หาก use case ไม่รองรับ

Guard submission
if (state.isSaving) return;
state = state.copyWith(isSaving: true);
try {
  await _saveTask();
} finally {
  state = state.copyWith(isSaving: false);
}

ข้อผิดพลาดที่พบบ่อย

  • เรียก async function โดยไม่ await แล้ว error หลุดจาก flow
  • catch Object ทุกชั้นและคืนข้อความ “Something went wrong”
  • ใช้ Stream สำหรับ request ครั้งเดียวจน lifecycle ซับซ้อน
  • ใช้ BuildContext หลัง await โดยไม่ตรวจ mounted
  • อนุญาตกด Save ซ้ำจนเกิด duplicate record
