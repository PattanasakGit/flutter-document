เป้าหมายของบท

  • มอง Riverpod เป็น dependency/state graph ไม่ใช่ global variable
  • เลือก watch, read และ listen
  • สร้าง controller ที่รับ dependency ผ่าน provider
  • override provider ใน test โดยไม่เรียก network/plugin

Provider graph

Test controller สามารถ override repository provider แล้วใช้ graph ส่วนที่เหลือจริง โดยไม่สร้าง mock ของทุก function

Provider สำหรับ dependency

Annotation-based provider
@riverpod
TaskRepository taskRepository(Ref ref) {
  return TaskRepositoryImpl(
    ref.watch(taskLocalDatasourceProvider),
  );
}

Generated provider เพิ่ม compile-time type และชื่อที่สม่ำเสมอ หลังแก้ annotation ต้องรัน build_runner และ review generated diff

Notifier/controller

Riverpod controller
@riverpod
class TaskListController extends _$TaskListController {
  @override
  TaskListState build() {
    return const TaskListState.loading();
  }

  Future<void> load() async {
    final getTasks = ref.read(getTasksProvider);
    final result = await getTasks();
    state = switch (result) {
      Success(:final data) => TaskListState.ready(tasks: data),
      Error(:final failure) => TaskListState.failed(failure: failure),
    };
  }
}

watch, read, listen

APIใช้เมื่อตัวอย่าง
ref.watchค่าที่เปลี่ยนแล้วต้อง recompute/rebuildWidget watch task state
ref.readอ่านครั้งเดียวใน event/methodonPressed เรียก controller
ref.listenทำ presentation side effect จาก transitionfailure ใหม่แสดง SnackBar
อย่าใช้ read เพื่อหลบ rebuild ถ้า UI แสดงค่าที่เปลี่ยน ต้อง watch ค่าอย่างแม่นยำหรือใช้ select ไม่ใช่ read แล้วปล่อย UI stale

Provider override ใน test

ProviderContainer
final container = ProviderContainer(
  overrides: [
    taskRepositoryProvider.overrideWithValue(fakeRepository),
  ],
);
addTearDown(container.dispose);

await container.read(taskListControllerProvider.notifier).load();
expect(
  container.read(taskListControllerProvider),
  isA<TaskListReady>(),
);

autoDispose และ keepAlive

Provider ที่ไม่มี listener อาจถูก dispose ตาม declaration/lifecycle อย่า keepAlive ทุกตัวเพื่อแก้ “state หาย” ก่อนวิเคราะห์ ownership Session อาจอยู่ระดับ app แต่ form draft อาจควรถูกทิ้งเมื่อออกหน้า

ลด rebuild ด้วย select เมื่อมีหลักฐาน

Watch field ที่ UI ใช้
final completedCount = ref.watch(
  taskListControllerProvider.select(
    (state) => state.completedCount,
  ),
);

ใช้เมื่อ profiling พบ subtree rebuild จาก field อื่นจริง อย่าเริ่มด้วย select ทุก fieldจน state API แตกละเอียดและอ่านยาก

ข้อผิดพลาดที่พบบ่อย

  • เรียก ref.watch ใน onPressed callback
  • สร้าง provider global ที่ไม่มี owner/cleanup policy
  • ให้ controller รับ BuildContext
  • override controller ทั้งตัวทั้งที่ต้องการเปลี่ยน repository boundary
  • ลืม dispose ProviderContainer ใน test
