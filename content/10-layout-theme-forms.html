เป้าหมายของบท

  • ใช้กฎ constraints → size → position วิเคราะห์ layout
  • เลือก Row, Column, Flex, Stack, scroll และ LayoutBuilder
  • ใช้ Theme token แทน hardcoded style กระจาย
  • สร้าง form ที่ keyboard, validation และ accessibility ทำงานร่วมกัน

Constraints ลง, Size ขึ้น, Parent วาง

ต่างจาก CSS Flutter child ไม่เลือกตำแหน่งบนหน้าจอเอง Parent ส่ง min/max constraints ให้ child เลือก size ภายในช่วง แล้ว parent จึงกำหนด offset
Responsive width
LayoutBuilder(
  builder: (context, constraints) {
    final wide = constraints.maxWidth >= 900;
    return wide
        ? Row(children: [Expanded(child: list), SizedBox(width: 360, child: form)])
        : Column(children: [list, form]);
  },
)

Row, Column, Expanded และ Flexible

  • Row ส่ง horizontal constraint ที่อาจ unbounded ให้ non-flex children
  • Expanded บังคับใช้พื้นที่ที่เหลือตาม flex
  • Flexible อนุญาต child เล็กกว่าส่วนแบ่ง
  • MainAxisSize.min ให้ Flex หดตาม children เมื่อ constraint อนุญาต
ป้องกัน text overflow
Row(
  children: [
    const Icon(Icons.task_alt),
    const SizedBox(width: 12),
    Expanded(
      child: Text(
        task.title,
        maxLines: 2,
        overflow: TextOverflow.ellipsis,
      ),
    ),
  ],
)

Scroll และ unbounded constraint

SingleChildScrollView ส่ง unbounded constraint ตามแกน scroll จึงห้ามวาง Expanded ที่ต้องการพื้นที่เหลือไม่จำกัดในแกนนั้น สำหรับรายการยาวใช้ ListView.builder เพื่อ lazy build

Responsive ไม่เท่ากับ device detection

ตัดสินจากพื้นที่ที่ component ได้รับด้วย LayoutBuilder มากกว่าถามว่าเป็น phone/tablet เพราะ split screen และ Web window ทำให้ device เดิมมีหลาย constraint

เครื่องมือใช้เมื่อหลีกเลี่ยง
LayoutBuilderlayout ตาม parent constraintsอ่านทั้งจอเมื่อ component อยู่ pane เล็ก
MediaQueryscreen size, text scale, padding, keyboardhardcode device model
SafeAreaหลบ notch/system insetsซ้อนหลายชั้นจน padding เกิน
OrientationBuilderlayout ตาม orientation เมื่อมีเหตุผลบังคับ portrait เพื่อซ่อน bug

void _submit() {

Controller ที่สร้างใน State ต้อง dispose, field ต้องมี visible label, error อยู่ใกล้ field และ submit button แสดง loading/disable ระหว่าง async

Accessibility baseline

  • touch target อย่างน้อย 48×48dp สำหรับ Material action
  • รองรับ text scale โดยไม่ใช้ fixed height ครอบ Text
  • tooltip/semantic label สำหรับ icon-only action
  • สีไม่ใช่ตัวบอกสถานะอย่างเดียว; ใช้ text/icon ร่วม
  • focus order ตามลำดับการอ่านและ keyboard submit ทำงาน

ข้อผิดพลาดที่พบบ่อย

  • วาง Expanded ใน scroll axis ที่ unbounded
  • ใช้ width ตาม device name แทน constraint
  • กำหนด height ของ text card ตายตัวจน text scale ล้น
  • ใช้ placeholder แทน label
  • ลืม dispose TextEditingController/FocusNode
