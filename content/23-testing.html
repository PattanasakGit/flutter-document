เป้าหมายของบท

  • เลือก test level จากความเสี่ยง ไม่ใช่จากเปอร์เซ็นต์ coverage
  • ทดสอบ Domain, Repository, Riverpod controller, Widget และ Router แยกบทบาทกัน
  • ใช้ fake ที่ deterministic และ override dependency ผ่าน ProviderContainer
  • สร้าง critical-flow integration test โดยไม่ทำให้ test suite เปราะ

Test portfolio ที่เหมาะกับ Boilerplate

รูปทรงไม่ได้กำหนดสัดส่วนตายตัว ให้เพิ่ม test ตรง boundary ที่ความเสียหายสูง และคง end-to-end ไว้เฉพาะ flow ที่ต้องพิสูจน์หลายชั้นร่วมกันจริง ๆ

AAA และชื่อ test แบบ behavior

task_test.dart
test('rename trims the title and preserves task identity', () {
  // Arrange
  final task = Task(id: 't-1', title: 'Draft guide');

  // Act
  final renamed = task.rename('  Publish guide  ');

  // Assert
  expect(renamed.id, task.id);
  expect(renamed.title, 'Publish guide');
});

ชื่อ test บอก precondition และ outcome ที่สำคัญ หลีกเลี่ยงชื่อ calls repository once ถ้าจำนวนครั้งไม่ใช่ contract ของระบบ

Repository test ที่ boundary

task_repository_impl_test.dart
test('maps transport records to domain tasks', () async {
  final source = FakeTaskDataSource(records: [
    const TaskRecord(id: '1', title: 'Read tests', completed: false),
  ]);
  final repository = TaskRepositoryImpl(
    datasource: source,
    idGenerator: () => 'task-test-1',
    clock: () => DateTime(2026, 7, 24),
    errorMapper: const ErrorMapper(),
    logger: const NoOpAppLogger(),
  );

  final result = await repository.loadTasks();

  expect(result, isA<Success<List<Task>>>());
  final tasks = (result as Success<List<Task>>).value;
  expect(tasks.single.title, 'Read tests');
});

Fake ควรจำลอง contract ด้วยข้อมูลจริงขนาดเล็ก ไม่จำลอง implementation detail ของ Dio หรือฐานข้อมูล หาก mapping พัง test นี้ต้อง fail

Controller test ด้วย ProviderContainer

task_controller_test.dart
final container = ProviderContainer(
  overrides: [
    taskRepositoryProvider.overrideWithValue(fakeRepository),
  ],
);
addTearDown(container.dispose);

final states = <AsyncValue<TaskViewState>>[];
final subscription = container.listen(
  taskControllerProvider,
  (_, next) => states.add(next),
  fireImmediately: true,
);
addTearDown(subscription.close);

await container.read(taskControllerProvider.notifier).create('Ship app');

expect(states.last.requireValue.visibleTasks.single.title, 'Ship app');

อ่าน controller ผ่าน graph จริง แต่ override เฉพาะ external boundary วิธีนี้ตรวจ dependency wiring ได้มากกว่าการสร้าง controller ตรง ๆ

Widget test จากมุมผู้ใช้

task_list_page_test.dart
await tester.pumpWidget(
  ProviderScope(
    overrides: [taskRepositoryProvider.overrideWithValue(fakeRepository)],
    child: const MaterialApp(home: TaskListPage()),
  ),
);
await tester.pumpAndSettle();

expect(find.text('Draft developer guide'), findsOneWidget);
await tester.tap(find.bySemanticsLabel('ทำงาน Draft developer guide ให้เสร็จ'));
await tester.pump();
expect(fakeRepository.saved.single.isCompleted, isTrue);

Prefer text, role, label และ key ที่มีความหมายต่อผู้ใช้ หลีกเลี่ยง finder ที่ผูกกับลำดับ widget หรือ class ภายในซึ่ง refactor แล้ว behavior ยังเดิม

ข้อผิดพลาดที่พบบ่อย

  • mock ทุก class จน test พิสูจน์เพียง mock configuration
  • ใช้ pumpAndSettle กับ animation/stream ที่ไม่มีวัน settle
  • assert implementation detail แทน observable behavior
  • ไล่ coverage 100% แต่ critical redirect และ failure path ไม่ถูกทดสอบ
  • test ผ่านทีละไฟล์ แต่ไม่รัน full suite ก่อนส่งงาน
