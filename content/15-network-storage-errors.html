เป้าหมายของบท

  • ติดตาม request/response ผ่าน Data → Domain → Application → UI
  • แยก DTO จาก Entity และตรวจ schema ที่ boundary
  • แปลง transport exception เป็น typed failure
  • เข้าใจ secure storage abstraction และข้อกำหนดราย platform

External data pipeline

UI ไม่อ่าน status code และ Domain ไม่รู้ JSON key Repository เป็นจุดรวม mapping จาก data representation ไป application result

Dio client responsibility

Typed decode callback
Future<T> get<T>(
  String path, {
  required T Function(Object? data) decode,
}) async {
  try {
    final response = await _dio.get<Object?>(path);
    return decode(response.data);
  } on DioException catch (error) {
    throw _errorMapper.mapDioException(error);
  }
}

ApiClient ซ่อน Response และ DioException แต่ decoder เองอาจ throw schema exception จึงต้องกำหนดว่า datasource จะแปลง error นั้นตรงไหนและเขียน malformed-payload test

DTO ไม่ใช่ Entity

Mapping
final class TaskDto {
  const TaskDto({
    required this.id,
    required this.title,
    required this.completed,
  });

  final String id;
  final String title;
  final bool completed;

  Task toEntity() => Task(
    id: id,
    title: title.trim(),
    description: '',
    isCompleted: completed,
  );
}

DTO เปลี่ยนตาม API contract, Entity เปลี่ยนตาม product/domain การแยกทำให้ API field rename ไม่บังคับทุก Widget เปลี่ยน

Repository เป็น source-of-truth policy

Repository ตัดสินว่าจะอ่าน remote/local/cache อย่างไร map external exception เป็น Failure และคืน Entity ไม่ควรเป็นเพียงชื่อใหม่ของ Dio method

Secure storage abstraction

Business-neutral interface
abstract interface class SecureStorage {
  Future<String?> read(String key);
  Future<void> write(String key, String value);
  Future<void> delete(String key);
}

Feature ใช้ abstraction ไม่ import plugin โดยตรง แต่ abstraction ไม่ทำให้ platform config หายไป iOS ต้องตรวจ entitlements, Android ต้องตรวจ backup/ cipher policy และ Web ต้องใช้ secure hosting/header ตาม plugin requirement

Token ไม่เท่ากับ Session

การเก็บ access token อย่างเดียวไม่พอ ต้องมี initialization, user identity, expiry, refresh, 401 policy, clear-on-logout และ route coordination อย่าให้ router เห็น anonymous ขณะที่ token เก่ายังถูก interceptor ส่ง

ข้อผิดพลาดที่พบบ่อย

  • คืน Dio Response จาก repository
  • ใช้ Entity เป็น JSON DTO โดยตรงทุกกรณี
  • จับทุก Object เป็น UnknownFailure แล้วซ่อน programming bug
  • คิดว่าใช้ secure storage package แล้ว platform config สมบูรณ์อัตโนมัติ
  • log header/body ที่มี token หรือ password ใน production
