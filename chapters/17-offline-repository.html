Capstone: Offline Datasource และ Repository

สร้าง deterministic in-memory datasource และแปลง external record ผ่าน repository boundary

เวลาอ่าน 70 นาที ระดับ กลาง in-memory datasource repository mapping offline deterministic

เป้าหมายของบท

  • สร้าง runnable app ที่ไม่พึ่ง network
  • แยก datasource record จาก domain entity
  • ให้ repository เป็น mapping/failure boundary
  • ทดสอบ create/update/toggle/delete แบบ deterministic

เหตุใด onboarding ใช้ Offline-first

Public API เปลี่ยน, rate-limit หรือ offline ได้ ทำให้ผู้เรียนสับสนระหว่าง architecture bug กับบริการภายนอก In-memory datasource ให้ feedback loop แน่นอนและทำให้ test ทุกเครื่องได้ผลเดียวกัน

Datasource record

data/datasources/task_local_datasource.dart
final class TaskRecord {
  const TaskRecord({
    required this.id,
    required this.title,
    required this.description,
    required this.completed,
    required this.createdAtIso,
  });

  final String id;
  final String title;
  final String description;
  final bool completed;
  final String createdAtIso;
}

แม้ in-memory record คล้าย entity เรายังแยกเพื่อแสดง boundary และเตรียม เปลี่ยน record เป็น database/JSON ได้โดย Domain ไม่เปลี่ยน

InMemory datasource

Deterministic implementation
final class InMemoryTaskDatasource {
  InMemoryTaskDatasource({
    List<TaskRecord> seed = const [],
  }) : _records = [...seed];

  final List<TaskRecord> _records;

  Future<List<TaskRecord>> readAll() async {
    return List.unmodifiable(_records);
  }

  Future<TaskRecord> upsert(TaskRecord record) async {
    final index = _records.indexWhere((item) => item.id == record.id);
    if (index == -1) {
      _records.add(record);
    } else {
      _records[index] = record;
    }
    return record;
  }
}

คืน unmodifiable snapshot ป้องกัน repository/caller mutate source โดยไม่ผ่าน datasource method การ inject seed ทำให้ test สร้าง scenario ได้ชัด

Inject ID และ Clock

Deterministic dependencies
typedef IdGenerator = String Function();
typedef Clock = DateTime Function();

TaskRepositoryImpl(
  datasource,
  idGenerator: () => 'task-test-1',
  clock: () => DateTime(2026, 7, 24),
);

ถ้า repository เรียก current time/random id โดยตรง test ต้องเดาผล การ inject function เล็กทำให้ production ใช้ของจริงและ test ใช้ค่าคงที่

Repository mapping

TaskRepositoryImpl
Task _toEntity(TaskRecord record) {
  return Task.restore(
    id: record.id,
    title: record.title,
    description: record.description,
    isCompleted: record.completed,
    createdAt: DateTime.parse(record.createdAtIso),
  );
}

TaskRecord _toRecord(Task task) {
  return TaskRecord(
    id: task.id,
    title: task.title,
    description: task.description,
    completed: task.isCompleted,
    createdAtIso: task.createdAt.toIso8601String(),
  );
}

Repository behavior tests

  • read คืน seed ตามลำดับและ caller แก้ list ไม่ได้
  • create trim/validate ผ่าน domain path และใช้ injected id/time
  • update รักษา id/createdAt
  • toggle task ที่ไม่มีคืน NotFoundFailure
  • delete แล้ว read ไม่พบ
  • datasource exception ถูก map เป็น UnknownFailure โดยไม่เปิด internal message ให้ UI

Compose ใน provider

tasks_providers.dart
@riverpod
InMemoryTaskDatasource taskLocalDatasource(Ref ref) {
  return InMemoryTaskDatasource(seed: TaskSeed.defaults);
}

@riverpod
TaskRepository taskRepository(Ref ref) {
  return TaskRepositoryImpl(
    ref.watch(taskLocalDatasourceProvider),
  );
}

ข้อผิดพลาดที่พบบ่อย

  • เรียก DateTime.now/random ใน test path โดย inject ไม่ได้
  • คืน internal mutable list
  • ให้ datasource คืน Result ซึ่งเป็น application concern ทุก implementation
  • เขียน repository เป็น pass-through จนไม่มี mapping/policy
  • ทำ offline datasource เป็น global singleton นอก provider lifecycle

Checkpoint ก่อนเดินต่อ

  1. อธิบายหัวข้อนี้ด้วยภาษาของตนเองโดยไม่เปิดคู่มือ
  2. ชี้ไฟล์หรือคำสั่งใน Boilerplate ที่สัมพันธ์กับบทนี้ได้
  3. รันตัวอย่างหรือ verification ที่บทกำหนดและอ่านผลลัพธ์ได้
