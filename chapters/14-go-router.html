GoRouter, Redirect และ Authentication Guard

ออกแบบ route table, named route, redirect policy, unknown route และ refresh จาก auth state

เวลาอ่าน 56 นาที ระดับ กลาง GoRouter redirect guard deep link route session

เป้าหมายของบท

  • กำหนด route table และ named paths ที่มีเจ้าของชัด
  • เขียน redirect เป็น policy ที่ deterministic
  • เชื่อม auth state กับ router refresh โดยไม่เกิด loop
  • ทดสอบ signed-in, signed-out และ unknown route

Route table

Typed constants
abstract final class AppRoutes {
  static const login = '/login';
  static const home = '/';
  static const tasks = '/tasks';
}

รวม path policy ไว้จุดเดียว ลด string literal กระจาย แต่ feature ยัง export page/public route surface เท่าที่ router ต้องใช้

Authentication guard flow

Session ต้องมี initializing state เพื่อไม่ redirect ไป login ก่อนอ่าน storage เสร็จ และควรเก็บ intended location สำหรับกลับหลัง authentication

Redirect policy ที่ test แยกได้

Pure policy
String? redirectFor({
  required String location,
  required bool isAuthenticated,
}) {
  final public = location == AppRoutes.login;
  if (!isAuthenticated) {
    return public ? null : AppRoutes.login;
  }
  if (public) return AppRoutes.home;
  return null;
}

Default deny เมื่อ signed-out ทำให้ route ใหม่ไม่เปิดโดยลืม guard แต่ production session ต้องเพิ่ม initializing/expired state มากกว่า bool

ประกอบ GoRouter

Router provider
GoRouter(
  initialLocation: AppRoutes.home,
  refreshListenable: refreshNotifier,
  redirect: (context, state) => redirectFor(
    location: state.matchedLocation,
    isAuthenticated: ref.read(authenticationSessionProvider) != null,
  ),
  routes: [
    GoRoute(path: AppRoutes.login, builder: (_, __) => const LoginPage()),
    GoRoute(path: AppRoutes.home, builder: (_, __) => const HomePage()),
    GoRoute(path: AppRoutes.tasks, builder: (_, __) => const TaskListPage()),
  ],
)

go, push และ back stack

Actionความหมายใช้เมื่อ
context.goเปลี่ยน location ตาม declarative routetop-level destination
context.pushเพิ่ม page บน stackdetail/subflow ที่กลับได้
context.popย้อน stackปิด detail/form เมื่อมี parent
named routeอ้าง route identityลด coupling กับ path format

Router test

Widget/router behavior
await tester.pumpWidget(
  ProviderScope(
    overrides: [authenticationSessionProvider.overrideWithValue(null)],
    child: const App(),
  ),
);

router.go('/tasks');
await tester.pumpAndSettle();
expect(find.byType(LoginPage), findsOneWidget);

ป้องกัน redirect loop

  • เมื่ออยู่ปลายทางที่ถูกต้องให้คืน null
  • อย่า mutate auth state ภายใน redirect
  • refresh เฉพาะเมื่อ state ที่ guard ใช้เปลี่ยน
  • แยก unknown-route presentation ออกจาก auth policy

ข้อผิดพลาดที่พบบ่อย

  • guard จาก LoginController UI state แทน session abstraction
  • redirect ก่อน session restore เสร็จ
  • ใช้ push สำหรับ top-level route จน back stack ซ้ำ
  • เปิด route ใหม่แต่ไม่มี signed-out test
  • คืน location เดิมซ้ำจาก redirect จน loop

Checkpoint ก่อนเดินต่อ

  1. อธิบายหัวข้อนี้ด้วยภาษาของตนเองโดยไม่เปิดคู่มือ
  2. ชี้ไฟล์หรือคำสั่งใน Boilerplate ที่สัมพันธ์กับบทนี้ได้
  3. รันตัวอย่างหรือ verification ที่บทกำหนดและอ่านผลลัพธ์ได้
