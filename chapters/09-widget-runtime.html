Widget, Element, RenderObject และ BuildContext

เข้าใจสาม tree, identity, rebuild, layout และ paint โดยไม่คิดว่า Widget คือ DOM node

เวลาอ่าน 60 นาที ระดับ พื้นฐาน Widget Element RenderObject BuildContext key rebuild repaint

เป้าหมายของบท

  • อธิบาย Widget, Element และ RenderObject แยกจากกัน
  • เข้าใจว่า build ถูกเรียกซ้ำได้และต้องไม่มี external side effect
  • ใช้ BuildContext ตามตำแหน่งใน tree
  • รู้ว่า Key แก้ identity problem แบบใด

สาม tree ทำงานร่วมกัน

Widget tree เปลี่ยนได้ทุก frame แต่ Element และ RenderObject ถูก reuse เมื่อ runtimeType/key/position จับคู่กันได้

Build method เป็น pure-ish description

StatelessWidget
final class TaskCount extends StatelessWidget {
  const TaskCount({required this.count, super.key});
  final int count;

  @override
  Widget build(BuildContext context) {
    final textTheme = Theme.of(context).textTheme;
    return Text('$count tasks', style: textTheme.titleMedium);
  }
}

build อ่าน input และ inherited dependencies แล้วคืน Widget อย่าเรียก API, เขียน storage หรือ mutate provider ใน build เพราะ framework เรียกซ้ำได้จาก parent rebuild, theme, locale, media query หรือ state

BuildContext คือ Element location

Theme.of(context) เดินขึ้น tree หา inherited value ที่ใกล้ที่สุด Context เหนือ provider/theme ใหม่จะมองไม่เห็นค่าที่สร้างใต้ตนเอง

Builder สร้าง context ใต้ Theme
Theme(
  data: darkTheme,
  child: Builder(
    builder: (innerContext) {
      return Text(
        'Uses dark theme',
        style: Theme.of(innerContext).textTheme.bodyLarge,
      );
    },
  ),
)

StatefulWidget แยก configuration กับ mutable state

Local UI state
final class PasswordField extends StatefulWidget {
  const PasswordField({super.key});

  @override
  State<PasswordField> createState() => _PasswordFieldState();
}

final class _PasswordFieldState extends State<PasswordField> {
  var _obscure = true;

  @override
  Widget build(BuildContext context) {
    return TextField(
      obscureText: _obscure,
      suffixIcon: IconButton(
        tooltip: _obscure ? 'Show password' : 'Hide password',
        onPressed: () => setState(() => _obscure = !_obscure),
        icon: Icon(_obscure ? Icons.visibility : Icons.visibility_off),
      ),
    );
  }
}

Key และ identity

สถานการณ์Keyเหตุผล
static child ตำแหน่งเดิมไม่ต้องposition/runtimeType พอ
reorder task list ที่มี stateValueKey(task.id)state ตาม task ไม่ตาม index
เข้าถึง State จากภายนอกGlobalKey อย่างจำกัดมีต้นทุนและ coupling สูง
บังคับสร้าง subtree ใหม่UniqueKeyทำลาย identity เดิมทุกครั้ง

Rebuild ไม่เท่ากับ repaint ทั้งหมด

build สร้าง configuration ใหม่ แล้ว element update เฉพาะ diff RenderObject อาจไม่ต้อง layout/paint ถ้า property ที่เกี่ยวข้องไม่เปลี่ยน จึงควรวัดด้วย DevTools แทนกลัว build method ทุกตัว

ข้อผิดพลาดที่พบบ่อย

  • เก็บ Widget object เป็น mutable state แทนเก็บข้อมูลที่ใช้สร้าง Widget
  • เรียก API ใน build
  • ใส่ GlobalKey ทุก list item
  • ใช้ context ของ parent เพื่ออ่าน dependency ที่เพิ่งสร้างใต้ parent
  • คิดว่า const ห้าม parent rebuild ทั้งหมด

Checkpoint ก่อนเดินต่อ

  1. อธิบายหัวข้อนี้ด้วยภาษาของตนเองโดยไม่เปิดคู่มือ
  2. ชี้ไฟล์หรือคำสั่งใน Boilerplate ที่สัมพันธ์กับบทนี้ได้
  3. รันตัวอย่างหรือ verification ที่บทกำหนดและอ่านผลลัพธ์ได้
