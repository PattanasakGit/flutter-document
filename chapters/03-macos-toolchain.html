03 · ติดตั้ง Flutter toolchain บน macOS และ VS Code

A · Orientation & Setup · บทที่ 03

ติดตั้ง Flutter toolchain บน macOS และ VS Code

เตรียม Flutter SDK, Android, iOS, Web, emulator, simulator และ VS Code ให้ตรวจสอบได้

เวลาอ่าน 40 นาที ระดับ เริ่มต้น macOS VS Code Xcode Android Studio CocoaPods flutter doctor

เป้าหมายของบท

  • ติดตั้งส่วนประกอบที่จำเป็นโดยรู้ว่าแต่ละตัวรับผิดชอบอะไร
  • ใช้ flutter doctor -v เป็นหลักฐาน ไม่เดาจากอาการ
  • ตั้ง VS Code, Android emulator, iOS Simulator และ Web device
  • แยกปัญหา Flutter SDK ออกจาก platform SDK
อย่าติดตั้งแบบสุ่มตาม error แรก อ่าน target ที่ต้องรองรับก่อน หากทำ Web อย่างเดียว Xcode warning ไม่ block งาน แต่ถ้าจะ build iOS ต้องมี Xcode component และ license ครบ

Toolchain มีหลายชั้น

Flutter command orchestrates Dart และ platform toolchain แต่ไม่ได้รวม Android SDK หรือ iOS platform component ทั้งหมดไว้ด้วย

ติดตั้งและตรวจ Flutter

ใช้ Flutter stable ที่ตรงกับ .fvmrc ของ repository หากทีมใช้ FVM ให้ทุกคนเลือก version จากไฟล์เดียวกัน หากติดตั้ง SDK ตรง ให้ตรวจว่า flutter --version ตรง baseline

ตรวจ SDK และ PATH
which flutter
flutter --version
dart --version
flutter doctor -v

อ่าน path บรรทัดแรกเพื่อป้องกันการเรียก Flutter คนละชุดกับ VS Code หาก terminal กับ IDE แสดง version ต่างกัน ให้แก้ SDK path ไม่ใช่รัน flutter clean

ตั้งค่า VS Code

  1. ติดตั้ง extension Flutter ซึ่งติดตั้ง Dart extension ให้ด้วย
  2. เปิด repository root ที่มี pubspec.yaml ไม่เปิดเฉพาะ lib
  3. ใช้ Command Palette → Flutter: Select Device
  4. ตรวจ status bar ว่า SDK และ device ถูกชุด
  5. เปิด Settings และเปิด format on save สำหรับ Dart
.vscode/settings.json ตัวอย่าง
{
  "[dart]": {
    "editor.formatOnSave": true,
    "editor.rulers": [80]
  },
  "dart.flutterSdkPath": ".fvm/flutter_sdk"
}

ใส่ dart.flutterSdkPath เฉพาะเมื่อ repository ใช้ FVM และ path นั้นมีจริง อย่า commit path absolute ที่เป็นของเครื่องคนเดียว

Android setup

  1. ติดตั้ง Android Studio เพื่อจัดการ SDK แม้เขียนโค้ดใน VS Code
  2. SDK Manager: ติดตั้ง platform และ build tools ที่ Flutter รองรับ
  3. Device Manager: สร้าง emulator ที่ ABI เหมาะกับ Apple Silicon
  4. ยอมรับ license ด้วย flutter doctor --android-licenses
  5. รัน emulator แล้วตรวจด้วย flutter devices

iOS setup

  1. ติดตั้ง Xcode และเปิดครั้งแรกเพื่อให้ component initialization เสร็จ
  2. เลือก Command Line Tools ใน Xcode Settings → Locations
  3. ดาวน์โหลด iOS Simulator runtime ที่ project target ต้องใช้
  4. ติดตั้ง CocoaPods ตาม policy ของทีม
  5. เปิด Simulator แล้วตรวจด้วย flutter devices
iOS build error ที่ไม่ใช่ source error หาก Xcode รายงานว่า iOS platform version ไม่ถูกติดตั้ง ให้เพิ่ม component ใน Xcode Settings ก่อนแก้ Dart code

Web setup

ตรวจ Web device
flutter config --enable-web
flutter devices
flutter run -d chrome -t lib/main_development.dart

Web เหมาะกับ feedback loop เร็ว แต่ plugin เช่น secure storage มีข้อกำหนด ต่างจาก mobile จึงต้องมี platform verification ภายหลัง

อ่าน flutter doctor อย่างมีเหตุผล

สถานะความหมายการตัดสินใจ
[✓]component ผ่าน check ที่ doctor รู้จักยังต้อง build/test project จริง
[!]มี warning หรือ optional gapอ่าน target; อาจไม่ block งานปัจจุบัน
[✗]component ไม่พร้อมแก้ก่อนถ้า target นั้นอยู่ใน scope

ปัญหาที่พบบ่อย

  • มี Flutter หลายชุดใน PATH แล้ว VS Code ใช้คนละชุดกับ terminal
  • เปิด project ใน iCloud แล้ว generated build files ถูก duplicate
  • อัปเดต Xcode แต่ไม่ได้ดาวน์โหลด Simulator runtime ใหม่
  • สร้าง Android emulator x86 บน Apple Silicon โดยไม่จำเป็น
  • แก้ทุก doctor warning ทั้งที่ target ปัจจุบันเป็น Web เท่านั้น

Checkpoint ก่อนเดินต่อ

  1. อธิบายหัวข้อนี้ด้วยภาษาของตนเองโดยไม่เปิดคู่มือ
  2. ชี้ไฟล์หรือคำสั่งใน Boilerplate ที่สัมพันธ์กับบทนี้ได้
  3. รันตัวอย่างหรือ verification ที่บทกำหนดและอ่านผลลัพธ์ได้
