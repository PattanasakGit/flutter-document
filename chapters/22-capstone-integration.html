E · Task Management · บทที่ 22

Capstone: Route, Shell และ End-to-end Flow

เชื่อม Tasks เข้ากับ GoRouter และ Home โดยรักษา auth guard และ public feature surface

เวลาอ่าน 64 นาที ระดับ กลาง integration route public API home auth guard smoke

เป้าหมายของบท

  • เปิด Tasks ผ่าน public feature surface
  • เพิ่ม route โดยไม่ทำลาย authentication guard
  • เชื่อม Home action และ deep link
  • รัน feature tests และ smoke flow ครบ

Feature public surface

lib/features/tasks/tasks.dart
export 'presentation/pages/task_list_page.dart'
    show TaskListPage;

Router ต้องรู้เพียง page ที่เปิดได้ ไม่ต้อง import datasource, DTO, controller implementation หรือ generated providers ทั้งหมด

เพิ่ม route

app_router.dart
GoRoute(
  path: AppRoutes.tasks,
  name: 'tasks',
  builder: (context, state) => const TaskListPage(),
),

guard เดิม default deny signed-out route จึงปกป้อง /tasks โดยไม่เพิ่ม condition ต่อ route แต่ต้องมี test พิสูจน์ policy

Home entry point

Home action
AppButton(
  label: 'Open task manager',
  onPressed: () => context.go(AppRoutes.tasks),
)

ใช้ชื่อ action ที่บอกผลลัพธ์ ไม่ใช้ “Click here” และรักษา minimum touch target/keyboard semantics จาก shared button

End-to-end capstone flow

Flow นี้เป็น demo integration ไม่ใช่ production session เพราะ user restore, token expiry/refresh และ real authentication datasource ยังเป็น production gap

Route tests

Signed-out and signed-in
testWidgets('redirects signed-out tasks route to login', (tester) async {
  await tester.pumpWidget(buildTestApp(user: null));
  router.go('/tasks');
  await tester.pumpAndSettle();
  expect(find.byType(LoginPage), findsOneWidget);
});

testWidgets('renders tasks for an authenticated user', (tester) async {
  await tester.pumpWidget(buildTestApp(user: TestData.user));
  router.go('/tasks');
  await tester.pumpAndSettle();
  expect(find.byType(TaskListPage), findsOneWidget);
});

Verification ladder

จากเร็วไปกว้าง
flutter test test/features/tasks/domain
flutter test test/features/tasks/application
flutter test test/features/tasks/data
flutter test test/features/tasks/presentation
flutter test test/app/router
flutter analyze
flutter test

เมื่อ focused test fail แก้จุดนั้นก่อนรันทั้งหมด หลังทั้งหมดผ่านจึง build target จริงเพื่อจับ platform/compiler issue

Manual smoke checklist

  1. cold start แสดง Login
  2. invalid form ไม่เรียก repository
  3. demo login ไป Home
  4. เปิด Tasks และเห็น seed 3 รายการ
  5. filter/create/edit/toggle/delete ทำงาน
  6. large text และ narrow viewport ไม่ overflow
  7. sign out จาก Home แล้ว /tasks ถูก guard

ข้อผิดพลาดที่พบบ่อย

  • Router import internal provider/data files ของ Tasks
  • เพิ่ม route แต่ไม่ทดสอบ signed-out
  • ใช้ navigation เป็น business outcome ใน use case
  • ถือว่า widget tests แทน cold-start/plugin integration
  • เรียก demo flow ว่า production-ready

Checkpoint ก่อนเดินต่อ

  1. อธิบายหัวข้อนี้ด้วยภาษาของตนเองโดยไม่เปิดคู่มือ
  2. ชี้ไฟล์หรือคำสั่งใน Boilerplate ที่สัมพันธ์กับบทนี้ได้
  3. รันตัวอย่างหรือ verification ที่บทกำหนดและอ่านผลลัพธ์ได้
