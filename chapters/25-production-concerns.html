Environment, Security, Accessibility และ Localization

แยก Dart config จาก native flavors จัดการ secrets/session/storage และเตรียมแอปสำหรับผู้ใช้หลากหลาย

เวลาอ่าน 90 นาที ระดับ กลาง flavor secrets session secure storage accessibility i18n RTL

เป้าหมายของบท

  • แยก compile-time environment, native flavor และ runtime config
  • จัดการ session, secrets, storage และ network policy ตาม threat model
  • ทำ accessibility และ localization เป็นข้อกำหนด ไม่ใช่งานตกแต่งท้ายโครงการ
  • ระบุ production gap ของ Boilerplate และแอปตัวอย่างอย่างตรงไปตรงมา

Configuration สามชั้น

--dart-define ไม่แทน Xcode scheme/Gradle flavor และ remote config ไม่ควรถือ secret; เลือกชั้นจากเวลาที่ค่าถูกตัดสินและระดับความลับ

Environment entrypoint

lib/main_staging.dart
Future<void> main() async {
  await bootstrap(
    const AppConfig(
      environment: AppEnvironment.staging,
      apiBaseUrl: String.fromEnvironment(
        'API_BASE_URL',
        defaultValue: 'https://staging.invalid',
      ),
      enableVerboseLogs: true,
    ),
  );
}

ค่าใน client binary สามารถถูก inspect ได้ จึงใช้ environment define สำหรับ public configuration เท่านั้น ไม่ใส่ server secret, private signing key หรือ credential ที่ให้สิทธิ์ถาวร

อะไรเป็น secret และควรอยู่ที่ใด

ข้อมูลตำแหน่งเหตุผล
Backend private keyServer/secret manager เท่านั้นclient ปกป้องไม่ได้
CI signing credentialCI protected secretใช้เฉพาะ pipeline ที่อนุญาต
Short-lived access tokenMemory; restore ตาม policyลด exposure เมื่อเก็บถาวร
Refresh tokenSecure storageOS-protected persistence
Analytics public keyBuild config ได้ไม่ใช่ authorization secret
User preferencePreferences/local DBไม่ต้องใช้ secure storage ทุกค่า

Session lifecycle

  1. cold start อ่าน refresh material ผ่าน storage abstraction
  2. ตั้ง state เป็น restoring แทนรีบสรุป signed-out
  3. refresh กับ backend และหมุน token ตาม policy
  4. ให้ request interceptor retry ได้จำกัดครั้งและ serialize refresh
  5. ถ้า refresh ถูกปฏิเสธ ให้ clear local session และ redirect อย่างตั้งใจ
  6. sign out ต้อง revoke ฝั่ง server (ถ้ามี), clear memory/storage และ reset user-scoped cache
Demo auth ใน Boilerplate ไม่ใช่ production auth Fake credential และ in-memory session มีไว้สอน state/router wiring เท่านั้น ห้ามเพียงเปลี่ยน URL แล้วนำขึ้น production

Network hardening

  • ใช้ HTTPS และ platform network-security policy ที่เหมาะสม
  • ตั้ง connect/receive/send timeout แยกกัน
  • retry เฉพาะ idempotent/transient failure พร้อม backoff และ jitter
  • redact authorization, cookie และ personal payload จาก log
  • validate response schema ก่อน map เข้า domain
  • certificate pinning ใช้เมื่อ threat model ต้องการและมี rotation plan

Localization ตั้งแต่ data model

อย่าประกอบประโยคจาก fragment
// ไม่ควร: word order ใช้ไม่ได้กับทุกภาษา
Text('$count ' + context.l10n.tasksRemainingSuffix);

// ควร: ให้ translator เห็น message และ plural rule
Text(context.l10n.tasksRemaining(count));

ทดสอบข้อความยาว, plural, date/number format, Thai line breaking, ภาษา RTL และ locale fallback อย่าเก็บ translated display string เป็น domain status; เก็บ stable enum แล้วแปลที่ presentation

Privacy และ data lifecycle

  • เก็บข้อมูลเท่าที่ feature ต้องใช้และระบุ retention
  • ขอ permission ตอนมีเหตุผลที่ผู้ใช้เข้าใจได้
  • รองรับ export/delete account ตามข้อกำหนดของผลิตภัณฑ์และกฎหมาย
  • จำแนก analytics event กับ personal data ก่อนส่ง
  • ตรวจ third-party SDK และ privacy manifest/store disclosure

ข้อผิดพลาดที่พบบ่อย

  • ฝัง server secret ใน Dart แล้วคิดว่า obfuscation ป้องกันได้
  • ใช้ secure storage เป็นฐานข้อมูลทั่วไป
  • route ไป Login ระหว่าง restore session ทำให้หน้ากระพริบและ redirect ผิด
  • เริ่ม localization หลัง UI ทุกหน้าถูก hard-code แล้ว
  • ประกาศ production-ready จากการที่ release build compile ผ่านอย่างเดียว

Checkpoint ก่อนเดินต่อ

  1. อธิบายหัวข้อนี้ด้วยภาษาของตนเองโดยไม่เปิดคู่มือ
  2. ชี้ไฟล์หรือคำสั่งใน Boilerplate ที่สัมพันธ์กับบทนี้ได้
  3. รันตัวอย่างหรือ verification ที่บทกำหนดและอ่านผลลัพธ์ได้
