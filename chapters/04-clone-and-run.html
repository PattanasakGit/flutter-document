Clone, Generate, Run และตรวจ Boilerplate

นำ source ลงเครื่อง อ่าน config สร้าง generated code รัน environment และยืนยัน baseline ก่อนแก้ไข

เวลาอ่าน 36 นาที ระดับ เริ่มต้น git clone pub get build_runner environment demo login

เป้าหมายของบท

  • Clone source จาก GitHub และสร้าง working copy ที่สะอาด
  • เข้าใจลำดับ pub get → codegen → analyze → test → run
  • รัน Development, Staging และ Production composition อย่างถูก target
  • ยืนยัน baseline ก่อนสร้าง feature

Clone และตรวจ identity

Terminal
git clone git@github.com:PattanasakGit/flutter-boilerplate.git
cd flutter-boilerplate
git status --short --branch
git log -5 --oneline
flutter --version

ผลที่ต้องการคือ working tree ไม่มี modified/untracked source และ Flutter ตรงกับ baseline ใน .fvmrc ถ้าจะสร้าง product ใหม่ ให้สร้าง repository ใหม่หรือเปลี่ยน remote อย่างมีเจตนา อย่าเผลอ push กลับ starter

ติดตั้ง dependency และ generate

Bootstrap
flutter pub get
dart run build_runner build
git diff --exit-code

pub get อ่าน constraint จาก pubspec.yaml และใช้ exact graph จาก pubspec.lock ส่วน build_runner สร้าง Riverpod, Freezed และ JSON code หลังจาก generate แล้ว git diff --exit-code ต้องไม่พบ stale generated files ใน clean clone

เทียบกับ Next.js flutter pub get ใกล้กับ install จาก lockfile ส่วน build_runner คล้าย code generation step ไม่ใช่ dev server และ generated files ของ repository นี้ตั้งใจ commit เพื่อให้ clone วิเคราะห์ได้ทันที

รันแต่ละ environment

Entrypoints
flutter run -t lib/main_development.dart
flutter run -t lib/main_staging.dart
flutter run -t lib/main_production.dart

-t เลือก Dart entrypoint ต่างจาก native flavor ทั้งสาม composition ใช้ fake authentication เหมือนกันใน starter ปัจจุบัน Development เปิด logging/debug banner ส่วน Staging/Production ปิด

สำรวจ Authentication vertical slice

  1. กรอก demo@example.com และ password123
  2. สังเกต validation ก่อน repository ถูกเรียก
  3. สังเกต loading state ทำให้ปุ่มถูก disable
  4. หลัง success router redirect ไป Home
  5. กด Sign out แล้ว router กลับ Login

จากนั้นอ่านตาม flow:

Source trail

  → login_form.dart
  → login_controller.dart
  → login_use_case.dart
  → authentication_repository_impl.dart
  → authentication_remote_datasource.dart

Hot reload, hot restart และ cold start

Actionรักษา stateใช้เมื่อ
Hot reloadส่วนใหญ่รักษาแก้ UI/method body
Hot restartเริ่ม Dart state ใหม่แก้ initialization/provider graph
Cold startเริ่ม process/platform ใหม่ตรวจ bootstrap, session restore, plugin config

ก่อนใช้เป็น product ใหม่

  • เปลี่ยน package/app name และ reverse-domain identifiers
  • เปลี่ยน remote repository
  • กำหนด environment strategy และ native flavors
  • แทน fake datasource ด้วย implementation ที่ fail closed
  • ตั้ง signing, icons, localization, privacy และ observability

ปัญหาที่พบบ่อย

  • รัน flutter run โดยไม่ใส่ -t ทั้งที่ไม่มี default main
  • แก้ generated .g.dart ด้วยมือ
  • เห็น Production label แล้วคิดว่าเชื่อม backend จริง
  • ใช้ flutter clean เป็นคำตอบแรกโดยไม่อ่าน error
  • เริ่ม feature ขณะที่ baseline test เดิมยัง fail

Checkpoint ก่อนเดินต่อ

  1. อธิบายหัวข้อนี้ด้วยภาษาของตนเองโดยไม่เปิดคู่มือ
  2. ชี้ไฟล์หรือคำสั่งใน Boilerplate ที่สัมพันธ์กับบทนี้ได้
  3. รันตัวอย่างหรือ verification ที่บทกำหนดและอ่านผลลัพธ์ได้
