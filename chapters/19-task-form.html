Capstone: Create/Edit Form และ Validation

สร้าง form ที่ accessible, scroll-safe, ป้องกัน duplicate submit และแสดง error ใกล้ field

เวลาอ่าน 82 นาที ระดับ กลาง Form validation TextEditingController focus accessibility submit

เป้าหมายของบท

  • สร้าง form เดียวที่ใช้ create และ edit ได้
  • วาง validation ใกล้ input และ domain validation ที่ boundary
  • จัดการ controller/focus lifecycle
  • ป้องกัน duplicate submit และ unsaved dismissal

Form contract

TaskFormValue
final class TaskFormValue {
  const TaskFormValue({
    required this.title,
    required this.description,
  });

  final String title;
  final String description;
}

Widget คืน value ที่ typed ผ่าน callback ไม่ส่ง TextEditingController ออกไป controller/application จึงไม่ผูกกับ Flutter text input implementation

สองชั้นของ validation

ชั้นหน้าที่เหตุผล
Presentation validatorfeedback เร็ว, focus field, localized textUX
Domain/use caseบังคับ invariant แม้ถูกเรียกจากที่อื่นcorrectness

อย่าพึ่ง UI validator อย่างเดียว เพราะ import/script/AI call อื่นอาจเรียก repository โดยไม่ผ่าน form

Submit flow

Prevent duplicates
Future<void> _submit() async {
  if (_submitting) return;
  if (!_formKey.currentState!.validate()) {
    _titleFocusNode.requestFocus();
    return;
  }

  setState(() => _submitting = true);
  final success = await widget.onSubmit(
    TaskFormValue(
      title: _titleController.text,
      description: _descriptionController.text,
    ),
  );
  if (!mounted) return;
  setState(() => _submitting = false);
  if (success) Navigator.of(context).pop();
}

Keyboard และ scroll

  • ใช้ scrollable body เพื่อไม่ overflow เมื่อ keyboard เปิด
  • อ่าน MediaQuery.viewInsetsOf(context).bottom ถ้าทำ custom sheet padding
  • กำหนด textInputAction และ onFieldSubmitted ตามลำดับ
  • ปุ่ม Save ต้องเข้าถึงด้วย keyboard และ screen reader
  • อย่า fixed height ครอบข้อความ error/helper

Create กับ Edit

ส่ง initialValue ที่ optional เข้า form และกำหนด controller ใน initState ถ้า parent เปลี่ยน Task ขณะ State เดิมอยู่ ใช้ didUpdateWidget หรือ route สร้าง identity ใหม่ตาม use case

Unsaved changes

เปรียบเทียบ current text กับ initial value ก่อน dismiss หากต่างให้ confirm โดยเฉพาะ form ยาว อย่าขัด system back gesture โดยไม่มี alternative

Widget tests ที่จำเป็น

  • empty title แสดง error ใต้ field และไม่เรียก callback
  • valid input ส่ง trimmed value
  • ระหว่าง submit ปุ่ม disable/มี progress
  • submit success ปิด sheet
  • submit failure ยังเปิด form และแสดง recovery
  • 200% text scale ไม่ overflow

ข้อผิดพลาดที่พบบ่อย

  • ใช้ placeholder แทน label
  • validate ทุก keystrokeจนผู้ใช้เห็น error ก่อนพิมพ์จบ
  • ไม่ dispose controller/focus node
  • ปิด form แม้ save fail
  • ใช้ GlobalKey เพื่อเข้าถึง widget แทน callback/state flow

Checkpoint ก่อนเดินต่อ

  1. อธิบายหัวข้อนี้ด้วยภาษาของตนเองโดยไม่เปิดคู่มือ
  2. ชี้ไฟล์หรือคำสั่งใน Boilerplate ที่สัมพันธ์กับบทนี้ได้
  3. รันตัวอย่างหรือ verification ที่บทกำหนดและอ่านผลลัพธ์ได้
