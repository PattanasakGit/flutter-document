Functions, Classes, Immutability และ Generics

ออกแบบ API ด้วย named parameters, constructors, abstract interface, extension และ generic type

เวลาอ่าน 58 นาที ระดับ พื้นฐาน function class constructor interface extension generic immutable

เป้าหมายของบท

  • ออกแบบ function signature ที่ call site อ่านได้
  • ใช้ constructor, factory และ abstract interface ตาม responsibility
  • สร้าง immutable entity และ copy semantics
  • ใช้ generic type เก็บ type information ข้าม layer

Function เป็น value และมี typed signature

Functions
typedef TaskPredicate = bool Function(Task task);

List<Task> filterTasks(
  List<Task> tasks, {
  required TaskPredicate where,
}) {
  return tasks.where(where).toList(growable: false);
}

final open = filterTasks(
  tasks,
  where: (task) => !task.isCompleted,
);

Callback ใน Flutter เช่น VoidCallback หรือ ValueChanged<T> เป็น function type ไม่ต้องสร้าง interface สำหรับ event เล็กทุกตัว

Immutable Task class

Domain entity
final class Task {
  const Task({
    required this.id,
    required this.title,
    required this.description,
    required this.isCompleted,
    required this.createdAt,
  });

  final String id;
  final String title;
  final String description;
  final bool isCompleted;
  final DateTime createdAt;

  Task copyWith({
    String? title,
    String? description,
    bool? isCompleted,
  }) {
    return Task(
      id: id,
      title: title ?? this.title,
      description: description ?? this.description,
      isCompleted: isCompleted ?? this.isCompleted,
      createdAt: createdAt,
    );
  }
}

final class ห้าม extend/implement นอก library ในรูปแบบที่ compiler กำหนดและสื่อว่า entity ไม่ได้ออกแบบเป็น extension point Boilerplate ใช้ Freezed กับ model/state บางส่วนเพื่อลด boilerplate ของ equality/copy/union แต่ควรรู้ logic ที่ generated code ทำแทน

Constructor หลายแบบ

Named และ factory constructor
final class TaskId {
  const TaskId._(this.value);

  final String value;

  factory TaskId.parse(String raw) {
    final value = raw.trim();
    if (value.isEmpty) {
      throw const FormatException('Task id must not be empty');
    }
    return TaskId._(value);
  }
}
  • Generative constructor สร้าง instance ใหม่
  • Named constructor บอก use case เช่น Task.draft
  • Factory คืน cached instance/subtype/validated instance ได้
  • Private constructor ใช้ซ่อน creation path ภายใน library

Domain ประกาศสิ่งที่ต้องการ ส่วน Data เลือกวิธีทำ การพึ่ง contract ทำให้ test use case ด้วย fake repository และเปลี่ยน offline เป็น remote datasource ได้

Extension method

Presentation formatting
extension TaskFilterLabel on TaskFilter {
  String get label => switch (this) {
    TaskFilter.all => 'ทั้งหมด',
    TaskFilter.open => 'ยังไม่เสร็จ',
    TaskFilter.completed => 'เสร็จแล้ว',
  };
}

Extension เหมาะกับ behavior ที่สัมพันธ์กับ type แต่ไม่ควรแก้ type ต้นทาง อย่าใช้ซ่อน external I/O หรือ dependency ที่คนอ่านไม่เห็นจาก call site

Generics รักษา type ข้าม boundary

Typed result
sealed class Result<T> {
  const Result();
}

final class Success<T> extends Result<T> {
  const Success(this.data);
  final T data;
}

final class Error<T> extends Result<T> {
  const Error(this.failure);
  final Failure failure;
}

Result<Task> กับ Result<List<Task>> ใช้ flow เดียวกันแต่ compiler ยังรู้ data type ไม่ต้อง cast จาก Object

Composition ก่อน inheritance

Compose dependency
final class CreateTask {
  const CreateTask(this._repository);
  final TaskRepository _repository;

  Future<Result<Task>> call({
    required String title,
    String description = '',
  }) {
    // Validate then delegate.
  }
}

Use case ไม่ extend repository แต่รับ contract ผ่าน constructor จึงเปลี่ยน implementation และทดสอบได้โดยไม่สร้าง inheritance tree

ข้อผิดพลาดที่พบบ่อย

  • สร้าง base class ใหญ่ที่ทุก feature ต้อง extend
  • ใช้ factory ซ่อน network call จน creation มี side effect
  • ทำ entity mutable แล้ว controller เปลี่ยนค่าโดยไม่มี state transition
  • คืน Result<dynamic> ทำให้ generic ไม่มีประโยชน์
  • ใส่ UI label ใน domain ทั้งที่ต้อง localize ใน presentation

Checkpoint ก่อนเดินต่อ

  1. อธิบายหัวข้อนี้ด้วยภาษาของตนเองโดยไม่เปิดคู่มือ
  2. ชี้ไฟล์หรือคำสั่งใน Boilerplate ที่สัมพันธ์กับบทนี้ได้
  3. รันตัวอย่างหรือ verification ที่บทกำหนดและอ่านผลลัพธ์ได้
