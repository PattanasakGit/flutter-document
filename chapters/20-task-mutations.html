Capstone: Toggle, Update, Delete และ Feedback

จัดการ mutation, confirmation, concurrency, rollback decision และ user feedback

เวลาอ่าน 72 นาที ระดับ กลาง CRUD mutation optimistic confirmation delete feedback concurrency

เป้าหมายของบท

  • ออกแบบ update/toggle/delete เป็น explicit state transition
  • เลือก optimistic หรือ confirmed update ด้วย risk/latency
  • ยืนยัน destructive action และให้ feedback
  • จัดการ concurrent mutation อย่าง deterministic

Mutation flow

Controller เป็นจุด serialize operation ส่วน Presentation เป็นเจ้าของ confirmation และข้อความที่ผู้ใช้เห็น

Optimistic vs confirmed

แบบข้อดีต้นทุน
Confirmedstate ตรง source-of-truth, rollback ง่ายfeedback ช้าตาม I/O
OptimisticUI ตอบทันทีต้องเก็บ previous state, rollback, conflict/race policy

offline datasource เร็วมากจึงเริ่ม confirmed update เพื่อความชัด เมื่อใช้ remote API และ latency วัดได้จึงค่อยพิจารณา optimistic

Delete confirmation

Presentation confirmation
final confirmed = await showDialog<bool>(
  context: context,
  builder: (context) => AlertDialog(
    title: const Text('ลบงานนี้?'),
    content: Text('“${task.title}” จะถูกลบออกจากรายการ'),
    actions: [
      TextButton(
        onPressed: () => Navigator.pop(context, false),
        child: const Text('ยกเลิก'),
      ),
      FilledButton(
        onPressed: () => Navigator.pop(context, true),
        child: const Text('ลบงาน'),
      ),
    ],
  ),
);
if (confirmed == true && context.mounted) {
  await controller.delete(task.id);
}

Feedback ที่ดี

  • action loading: disable control ที่เกี่ยวข้อง ไม่ block ทั้งหน้าเสมอ
  • success: UI state เปลี่ยนและมี semantics/brief message
  • failure: บอกสาเหตุระดับผู้ใช้และ recovery เช่น retry
  • delete: ถ้า product risk สูง เพิ่ม Undo โดย repository รองรับ restore

Race และ stale result

ถ้าอนุญาตหลาย task mutate พร้อมกัน ให้ state track operation ต่อ id ไม่ใช้ bool เดียว disable ทั้ง list แต่ถ้า MVP เลือก serialize ให้เขียน policy และ test ชัด ตัวอย่างนี้ serialize mutation ทั้ง list, disable filter/reload ระหว่าง mutation และใช้ generation token ให้ load ล่าสุดชนะ จึงไม่ปล่อย pre-await snapshot หรือ request เก่าเขียนทับ state ใหม่

Mutation tests

  • toggle success เปลี่ยนเฉพาะ target task
  • toggle missing id แสดง failure และ list เดิมไม่หาย
  • edit invalid ไม่เรียก repository
  • delete cancel ไม่เรียก controller
  • delete confirm success เอา item ออก
  • กด action ซ้ำระหว่าง mutation ไม่เกิด duplicate call
  • filter/reload ระหว่าง mutation ไม่เปลี่ยน state
  • overlapping load ที่เก่ากว่า complete ทีหลังไม่เขียนทับผลใหม่

ข้อผิดพลาดที่พบบ่อย

  • ทำ optimistic update โดยไม่มี rollback
  • ลบจาก UI list แต่ไม่ลบ source-of-truth
  • ใช้สีแดงอย่างเดียวบอก destructive action โดยไม่มีข้อความ
  • Dialog ปิดแล้วใช้ context โดยไม่ตรวจ mounted
  • กด action ซ้ำได้ระหว่าง await

Checkpoint ก่อนเดินต่อ

  1. อธิบายหัวข้อนี้ด้วยภาษาของตนเองโดยไม่เปิดคู่มือ
  2. ชี้ไฟล์หรือคำสั่งใน Boilerplate ที่สัมพันธ์กับบทนี้ได้
  3. รันตัวอย่างหรือ verification ที่บทกำหนดและอ่านผลลัพธ์ได้
