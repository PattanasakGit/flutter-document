React/Next.js ↔ Flutter Glossary

วิธีอ่าน Glossary

คอลัมน์ React/Next.js เป็นสะพานเริ่มต้น ไม่ใช่ความหมายเท่ากันทุกมิติ ให้จำ Flutter concept และข้อจำกัดของ analogy เป็นหลัก

เมื่อใดควรหยุดเทียบกับ React

  • เมื่อกำลังแก้ layout: ใช้ constraints model ไม่แปล CSS property
  • เมื่อกำลังจัด lifecycle: ดู owner และ app lifecycle ไม่ copy dependency array
  • เมื่อกำลังทำ security: native token/storage ไม่เท่ากับ httpOnly cookie
  • เมื่อกำลัง profile: ดู Flutter frame pipeline ไม่เทียบ DOM repaint อย่างเดียว
  • เมื่อออกแบบ architecture: เริ่มจาก boundary/risk ไม่ copy folder จาก Next.js

ข้อผิดพลาดที่พบบ่อย

  • เรียก Widget ว่า DOM node จนพยายาม mutate มัน
  • ย้ายทุก server concern จาก Next.js มาไว้ใน mobile client
  • คิดว่า Riverpod คือ Redux store เดียวและทำ global state ทุกอย่าง
  • ใช้ secure storage เหมือน localStorage หรือ database
  • เชื่อ analogy โดยไม่อ่านคอลัมน์ข้อแตกต่าง

Checkpoint ก่อนเดินต่อ

  1. อธิบายหัวข้อนี้ด้วยภาษาของตนเองโดยไม่เปิดคู่มือ
  2. ชี้ไฟล์หรือคำสั่งใน Boilerplate ที่สัมพันธ์กับบทนี้ได้
  3. รันตัวอย่างหรือ verification ที่บทกำหนดและอ่านผลลัพธ์ได้
